## 1. Что мы строим

Публичная веб-стена, на которую любой человек может повесить анонимное текстовое сообщение ("стикер") с пометкой настроения. Стикер живёт **7 дней**, потом автоматически исчезает — вариант с накоплением слоями на месяцы сознательно НЕ строим сейчас, это возможное будущее направление.

- **Регион и язык:** Казахстан / русскоязычный СНГ. Весь интерфейс — на русском. Не проектируй мультиязычность заранее.
- **Анонимность:** без регистрации по email/телефону. Пользователь идентифицируется анонимным session-токеном (localStorage/cookie), не персональными данными.
- **Тон продукта:** тёплый, лёгкий, немного игровой — не корпоративный форум и не мрачная "стена плача".

## 2. Технический стек

| Слой | Выбор | Почему |
|---|---|---|
| Frontend | Next.js (App Router) + TypeScript + Tailwind CSS | Стандарт для большинства "вайб-кодинг" инструментов, хорошая поддержка Lovable/bolt/v0 |
| Backend + БД | Supabase (Postgres + Realtime + Auth опционально + Storage) | Бесплатный тариф достаточен для MVP, Realtime из коробки нужен для "живой" стены, реляционная модель хорошо ложится на схему ниже |
| Хостинг | Vercel (frontend) + Supabase Cloud (backend) | Бесплатные тарифы на старте, минимум DevOps |
| Модерация | OpenAI Moderation API (бесплатно для текста) + свой словарь запрещённых слов | Бесплатно, но покрытие рус/каз сленга слабое — словарь обязателен как дополнение |
| Платежи | Kaspi Pay (для рынка РК) | ⚠️ Не имеет простого универсального SDK как Stripe — для Фазы 3 закладывай **ручной/полуручной** флоу (см. раздел 6), не пытайся автоматически найти готовую интеграцию |

Секреты (`OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY` и т.д.) — только в серверных переменных окружения. **Service role key никогда не должен попадать в клиентский код** — частая ошибка именно с Supabase.

## 3. Модель данных

```sql
create table stickers (
  id uuid primary key default gen_random_uuid(),
  text text not null check (char_length(text) between 1 and 1000),
  mood text not null check (mood in ('happy','sad','angry','thoughtful','love')),
  position_x float not null,
  position_y float not null,
  rotation float not null default 0,
  decoration_id uuid references decorations(id),
  is_sponsored boolean not null default false,
  session_id text not null,
  likes_count int not null default 0,
  report_count int not null default 0,
  is_hidden boolean not null default false,
  created_at timestamptz not null default now(),
  expires_at timestamptz not null default (now() + interval '7 days')
);

create table reactions (
  id uuid primary key default gen_random_uuid(),
  sticker_id uuid references stickers(id) on delete cascade,
  session_id text not null,
  created_at timestamptz not null default now(),
  unique (sticker_id, session_id) -- один лайк на сессию
);

create table reports (
  id uuid primary key default gen_random_uuid(),
  sticker_id uuid references stickers(id) on delete cascade,
  reason text not null,
  created_at timestamptz not null default now()
);

create table decorations (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  price_kzt int not null,
  style_key text not null, -- 'rainbow-border' | 'gold-frame' | 'soft-glow' | 'starry-border'
  is_active boolean not null default true
);

create table purchases (
  id uuid primary key default gen_random_uuid(),
  session_id text not null,
  decoration_id uuid references decorations(id),
  amount_kzt int not null,
  payment_method text not null, -- 'kaspi' | 'manual'
  created_at timestamptz not null default now()
);
```

Мудрости (`mood`) для старта: `happy` 😊, `sad` 😢, `angry` 😠, `thoughtful` 🤔, `love` 🥰 — если по факту в макете набор другой, скажи мне, поменяем.

## 4. Дизайн-направление

Продолжаем визуальный язык уже готового макета, не изобретаем новый.

**Палитра (mood → фон карточки / акцент):**

| Настроение | Фон карточки | Акцент |
|---|---|---|
| Фон страницы | `#F1F0F5` (мягкий лавандово-серый) | — |
| Нейтральная карточка | `#FDFCFA` | `#2A2A2E` (текст) |
| 😊 happy | `#FFF6DA` | `#E3A93B` |
| 😢 sad | `#DFE9F6` | `#6B87AC` |
| 😠 angry | `#FBE3DD` | `#C1554A` |
| 🤔 thoughtful | `#E9E3F6` | `#8A79B8` |
| 🥰 love | `#FCE1EA` | `#C96E8D` |

**Типографика:** одна гуманистическая гротеска с полноценной кириллицей на все роли — например Manrope или Inter. **Не бери "рукописные"/декоративные шрифты для кириллицы** — у большинства из них слабое покрытие кириллических глифов, текст будет выглядеть криво. Характер достигается весом и размером (ExtraBold для заголовка "Стена"), а не сменой гарнитуры.

**Сигнатурный элемент (это то, что делает "Стену" узнаваемой, а не шаблонной):** карточка **визуально "выцветает" по мере приближения к удалению** — за последние ~24 часа жизни плавно снижается opacity и/или у одного угла появляется лёгкий "загиб" (как у настоящего отклеивающегося стикера). Это не декорация ради декорации — это прямая визуализация ключевой механики продукта (эфемерность).

**Layout:** карточки свободно разбросаны на холсте (как в макете), не жёсткая сетка. Для MVP — это **скроллируемый контейнер увеличенного размера с абсолютным позиционированием карточек внутри**, а НЕ полноценный pan/zoom холст уровня Figma/Miro — последнее избыточно сложно для MVP и не нужно, пока карточек мало. Полноценный зум/панорамирование — это уже Фаза 4, отдельно.

## 5. UI-спецификация (по макету)

**Шапка:** плавающая пилюля по центру — заголовок "Стена" + бейдж "сообщения [N]".

**Карточка стикера:**
- эмодзи настроения (левый верхний угол)
- таймстамп (правый верхний угол)
- текст сообщения (до 1000 символов)
- **новое:** маленький бейдж "исчезнет через N дн." — в макете этого не было, но это нужно добавить, чтобы автор понимал срок жизни своего сообщения
- ряд реакций: ❤ лайк, 💬 комментарий (можно оставить заглушкой в Фазе 1), ↗ поделиться
- если `is_sponsored = true` — визуально отличается (другая обводка) + подпись "Реклама" (юридически обязательна, не опционально)

**Композер (нижняя панель, докнута):**
- textarea, placeholder "Что у вас на уме?"
- живой счётчик "X/1000"
- выпадающий селектор настроения (эмодзи + подпись, напр. "😊 Радостное")
- кнопка отправки — неактивна, пока пусто или пока не прошла модерация

## 6. Функциональность по фазам

### Фаза 1 — Ядро + базовая модерация
- [ ] Создание стикера: текст + настроение → появляется на холсте почти в реальном времени (Supabase Realtime)
- [ ] Позиционирование: случайная позиция в границах холста с простым избеганием наложений (несколько попыток подобрать свободное место, затем допустить лёгкое наложение)
- [ ] Лимит 1000 символов — проверка и на клиенте, и на сервере
- [ ] **Каждый текст перед сохранением проверяется через OpenAI Moderation API; если flagged — сообщение отклоняется с понятной причиной автору.** Это часть Фазы 1, не откладывается.
- [ ] Автоматическое удаление по `expires_at` — через scheduled job (Supabase Edge Function по cron), а не только фильтрацией на клиенте: запись должна реально удаляться из БД
- [ ] Лайк (один на сессию на стикер)

### Фаза 2 — Полноценная защита (обязательна до реального трафика)
- [ ] Кнопка "Пожаловаться" с причиной; при 3 жалобах — стикер автоматически скрывается до ручной проверки
- [ ] Свой словарь запрещённых слов/сленга (рус/каз) как дополнение к OpenAI — она слабо ловит региональный сленг
- [ ] Rate limiting: не больше ~5-10 постов на сессию в час
- [ ] Простая админ-панель (защищена паролем) для просмотра и удаления жалоб/нарушений
- [ ] Страницы "Условия использования" и "Политика конфиденциальности" — с минимальным возрастным ограничением в тексте. (Нужен реальный юридический текст, не просто заглушка — платформа с пользовательским контентом несёт юридическую ответственность)

### Фаза 3 — Монетизация
- [ ] **Косметика (декорации):** магазин (модалка) с 4 стартовыми вариантами — радужная рамка, золотая рамка, мягкое свечение, звёздная рамка. Превью на примере стикера перед покупкой. Цены ₸500–1500. **Для v1 оплата может быть полуручной**: QR на перевод через Kaspi + админ вручную подтверждает и включает декорацию сессии — не трать время на полноценную платёжную интеграцию, пока не видно, что люди реально покупают.
- [ ] **Спонсорские стикеры:** визуально отличаются, обязательная подпись "Реклама", **не больше 1 на каждые 15–20 обычных стикеров в области видимости**. Вставляются вручную админом (первые 3-5 партнёров), самообслуживаемой рекламной платформы не строим.
- [ ] **Поддержка:** статическая ссылка/QR на перевод в Kaspi в футере — минимум усилий, низкий приоритет.

### Специально НЕ строим сейчас (не предлагай это как "улучшение")
- Вариант с накоплением слоями на месяцы / просмотр истории по слоям
- Мультиязычность / выход за пределы региона
- Самообслуживаемая рекламная платформа
- Нативные мобильные приложения (веб, адаптивный под мобильный — достаточно)
- Полноценный pan/zoom холст (см. раздел 4)

---

## 7. Нефункциональные требования

- Адаптивность под мобильный — приоритет, вероятно большинство трафика оттуда
- Никаких персональных данных сверх анонимного session-токена
- Стена не должна "тормозить" при паре сотен видимых стикеров — заложи базовую виртуализацию рендера (не рендерь DOM-узлы для стикеров вне видимой области), даже если сейчас стикеров мало
