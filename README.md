# Стена

Публичная веб-стена анонимных стикеров с настроением. Стикер живёт 7 дней и
исчезает. Полное ТЗ — `stena-project-spec.md` в этом репозитории (или в
`Downloads/stena-project-spec.md`, откуда оно изначально взято).

Реализованы все три фазы ТЗ: **Фаза 1** (ядро + базовая модерация),
**Фаза 2** (жалобы, словарь слов, rate limiting, админка, юр. страницы) и
**Фаза 3** (магазин декораций, спонсорские стикеры, поддержка через Kaspi).

## Стек

Next.js (App Router) + TypeScript + Tailwind CSS v4, Supabase (Postgres +
Realtime), OpenAI Moderation API.

## Настройка с нуля

### 1. Supabase-проект

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатный тариф).
2. В SQL Editor выполните по очереди все миграции из `supabase/migrations/`
   (`0001_init.sql`, `0002_reports.sql`, `0003_decorations_shop.sql`) —
   создадут таблицы, RLS-политики и RPC-функции (`like_sticker`,
   `report_sticker`).
3. Realtime должен быть включён для таблицы `stickers` (Database ->
   Replication -> `stickers` -> вкл.).
4. Возьмите `Project URL`, `anon public` key и `service_role` key
   (Settings -> API).

### 2. OpenAI API key

Получите ключ на [platform.openai.com](https://platform.openai.com/api-keys).
Moderation API бесплатен для текста.

### 3. Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните:

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...   # только сервер, не NEXT_PUBLIC_!
OPENAI_API_KEY=...
ADMIN_PASSWORD=...              # пароль для /admin (HTTP Basic Auth)
NEXT_PUBLIC_KASPI_PHONE=...     # опционально — реквизиты для магазина/поддержки
NEXT_PUBLIC_KASPI_QR_URL=...    # опционально — путь к QR-картинке в /public
```

`SUPABASE_SERVICE_ROLE_KEY` используется только в Route Handlers
(`app/api/**`) и в Server Components — никогда не уходит в браузер. Файл
`lib/supabase/admin.ts` защищён импортом `server-only`, чтобы случайное
использование в клиентском компоненте ломало сборку, а не утекало в рантайме.

### 4. Запуск локально

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Админ-панель — http://localhost:3000/admin
(браузер спросит логин/пароль; логин можно любой, важен пароль —
`ADMIN_PASSWORD`).

### 5. Автоудаление истёкших стикеров (cron)

Инструкции и код — `supabase/functions/expire-stickers/README.md`. Кратко:
деплой Edge Function по расписанию (или `pg_cron`, если он включён в проекте) —
раз в час удаляет из БД стикеры с `expires_at < now()`.

### 6. Kaspi-реквизиты (магазин декораций и поддержка)

Загрузите QR-код перевода Kaspi в `public/kaspi-qr.png` (или другое имя) и
укажите путь в `NEXT_PUBLIC_KASPI_QR_URL`; номер телефона — в
`NEXT_PUBLIC_KASPI_PHONE`. Оба показываются вместе везде, где нужна оплата
(магазин декораций, кнопка «Поддержать»); можно задать только один из них.

### 7. Деплой

- Frontend — Vercel (`vercel.com/new`), прописать те же переменные окружения
  в Project Settings -> Environment Variables (включая `ADMIN_PASSWORD`).
- Backend — Supabase Cloud, уже настроен на шаге 1.
- Basic Auth админ-панели полагается на HTTPS (пароль иначе идёт в открытом
  виде) — на Vercel HTTPS включён по умолчанию, для самостоятельного хостинга
  проверьте это отдельно.

## Модерация и защита (Фаза 2)

- **Порядок проверки** при создании стикера: длина -> rate limit (не больше
  8 постов на сессию в час) -> владение декорацией (если указана) -> словарь
  запрещённых слов -> OpenAI Moderation API. Дорогой вызов OpenAI — последним.
- **Словарь слов** (`lib/wordFilter.ts`) — стартовый список, не исчерпывающий.
  Расширяйте его силами модераторов/носителей языка по мере необходимости.
- **Жалобы**: кнопка 🚩 на каждом стикере. При 3 жалобах `report_sticker`
  атомарно скрывает стикер — он пропадает из `SELECT` по RLS и попадает в
  очередь `/admin`.
- **Известное ограничение**: если сторонний посетитель уже открыл стену и
  сообщение скрывается чужой третьей жалобой, у него карточка пропадёт не
  сразу через Realtime, а при следующей перезагрузке. Для MVP это приемлемо.
- **Админ-панель** (`/admin`, Basic Auth): жалобы/скрытые стикеры с действиями
  «Одобрить», «Скрыть», «Удалить навсегда».

## Монетизация (Фаза 3)

- **Магазин декораций** (кнопка 🎨 в шапке): 4 декорации из `decorations`
  (радужная рамка, золотая рамка, мягкое свечение, звёздная рамка, ₸500–1500),
  с превью на примере стикера. Оплата **полуручная**, без платёжной
  интеграции:
  1. пользователь жмёт «Купить» — видит сумму, реквизиты Kaspi и свой
     анонимный код сессии (полностью, для копирования);
  2. переводит деньги в Kaspi, код указывает в комментарии к переводу или
     сообщает администратору любым согласованным способом;
  3. администратор в `/admin` вставляет этот код и выбирает декорацию —
     `POST /api/admin/purchases` создаёт запись в `purchases`, декорация
     становится доступна сессии в композере.
  - Декорация привязывается к конкретному стикеру при создании (поле
    `decoration_id`), а не ко всей сессии разом — так и предусмотрено схемой
    БД. Сервер проверяет владение перед сохранением (`app/api/stickers/route.ts`),
    подделать `decorationId` в запросе нельзя.
- **Спонсорские стикеры**: администратор публикует их напрямую через форму
  в `/admin` (без модерации — контент уже проверен человеком). Обязательная
  подпись «Реклама» и другая обводка — в `StickerCard.tsx`. Плотность
  ограничена на рендере: не больше 1 спонсорского на ~15 обычных **в видимой
  области** холста (`WallCanvas.tsx`, `SPONSORED_RATIO`) — это соблюдается
  даже если несколько спонсорских стикеров случайно оказались рядом.
- **Поддержка** (кнопка 💛 в шапке): статичный блок с реквизитами Kaspi,
  без привязки к сессии/декорациям — минимум усилий, как и просило ТЗ.
- Ни один из потоков не требует платёжного SDK/вебхуков — вся оплата
  подтверждается человеком, как и предполагалось для v1.

## Известные ограничения (ожидаемо, не баг)

- Комментарии — кнопка-заглушка (по ТЗ).
- Полноценный pan/zoom холст сознательно не реализован — см. раздел 4 ТЗ.
- Юридические страницы (`/terms`, `/privacy`) содержат содержательный черновик
  реальных правил, но не заменяют проверку юристом перед коммерческим запуском.
- Самообслуживаемого магазина для рекламодателей нет — админ вручную
  публикует первые 3–5 партнёрских стикеров, как и указано в ТЗ.
- Визуальные стили декораций (`lib/decorations.ts`) — ориентировочные, чистый
  CSS без готового макета; легко заменить, тронув только этот файл.
